# 架构决策记录

这份文件记的是**为什么这么设计**，不是怎么实现。改架构前先读一遍，别把踩过的坑再踩一次。

---

## D1. 为什么必须有中心服务器

**结论：群聊和人类私聊必须有一台服务器做串行化；一对一（人 ↔ 自己的 AI、人 ↔ 别人的 AI）技术上不需要，但也不该单独做一套。**

### 推理过程

聊天和邮件的关键区别是**顺序就是语义**：

- 邮件：每封独立，"刚才说的那句"不存在
- 聊天：所有消息是一条连续的线，回复、引用、"你前面说的"全依赖顺序

一旦**有多个写者**（群里 N 个人、或两个人类私聊），就必须有一个地方把所有消息**排成一个所有人都一样的顺序**。这在分布式系统里叫全序广播，是经典难题。

自研去中心化方案（人人一台服务器）在这里会撞三堵墙：

| 墙 | 具体表现 |
|---|---|
| 共享注册表 | 两人同时用同一手机号在各自服务器注册，谁算数？复制表必然分叉，要避免分叉就得有唯一权威 —— 又回到中心 |
| 离线补发 | "从最晚下线的那台同步" 假设总有机器在线；小圈子恰恰是**同时离线概率最高**的场景，中间消息永久丢失 |
| 全序 | 各台服务器各自收消息，时钟不可信、并发发言无法定序；做错的表现很隐蔽（不同人看到的顺序不一样） |

手机号还有一层：11 位空间只有 10¹⁰，哈希存了也能被枚举反查，**"加密存储"不等于隐私**。

### 各场景的真实需求

| 场景 | 写者数 | 要服务器 | 原因 |
|---|---|---|---|
| 我和我的 AI | 1 | 不要 | 本机直连即可 |
| 我和别人的 AI | 1（AI 只是应答） | 技术上不要 | 写者唯一，`(设备号, 本地序号)` 就够定序 |
| 人和人私聊 | 2 | **要** | 两个写者，需要全序 |
| 群聊 | N | **要** | 全序 + 成员变动 + 离线补发 + 多 AI 协调 |

### 为什么不按"要不要服务器"分叉两套协议

1 对 1 走服务器**没有坏处**：延迟更低（不用等对方上线）、代码更少（复用 seq/SSE）、行为更一致。
而多一套投递语义 = 两套消息格式、两套重发、两套已读、两套调试路径 —— **多一倍 bug，换来的只是省掉一台你已经有的服务器**。

**所以：统一走服务器串行化。**

## D2. 服务器性能不是问题，在线才是

实测（2026-11-21，123 条消息的那个库）：

```
数据库 80 KB   进程内存 53 MB   平均每条消息 37 字节
```

推算 20 人规模：

| 项目 | 一年 |
|---|---|
| 消息 | 36.5 万条 |
| 文字库 | ~87 MB |
| 图片 | ~7 GB |

**瓶颈排序：磁盘（图片）> 带宽 > 内存（若同机跑 AI）> CPU ≈ 数据库。**

一个群的发消息速率是每 86 秒一条，SQLite 写入是微秒级。**最便宜的 1 核 1G 轻量服务器足够**，甚至树莓派。

升级的触发条件是：磁盘满 / 内存不够 / 同时几百人在线 —— 不是"人数"。

真正要警惕的是**图片**：200MB/人 的配额已经设了，将来还得加"清理 90 天前的图片"或挪到对象存储。文字存十年都不用管。

## D3. AI 跑在各自机器上，服务器不花 CPU

每个群绑定一个 DSH 会话，但**会话跑在接入者自己的电脑上**（通过 `bridge/nest-bridge.mjs` 反向连接）。

- 服务器只做转发和串行化，不跑模型
- 接入者的 skill / 工具 / 文件都在他自己机器上，服务器碰不到
- 代价：接入者的电脑关了，他那份 AI 就下线

## D4. AI 之间的相处规则（三条，两边实现一致）

| 情况 | 行为 |
|---|---|
| 别的 AI 说话 | **看见但不接**（进上下文，不触发回合） |
| 别的 AI @ 它 | 允许接一次 |
| AI 之间连续来回 > 3 轮 | 强制沉默，等真人发言归零 |

为什么不"直接忽略别的 AI"：忽略会让 AI 聊到一半失忆；"看见但不动嘴"既不失忆也不刷屏。

## D5. 账号分两种，AI 走钥匙不走密码

- 真人：手机号 + 密码 + 两个密保问题（无短信验证）
- AI：没有密码，只有**钥匙**（`NEST-AI-xxxx`，库中只存 sha256，明文只出现一次）
- 真人和 AI 在群里地位一样，但 AI 不能拉人、不能发邀请、不能加好友

## D6. 一次否决过的方案（别再提）

| 方案 | 否决原因 |
|---|---|
| 人人一台服务器 + 复制注册表 | 需要共识；离线补发没有权威；实现成本高一个数量级 |
| 一对一用邮件式、群用服务器式 | 两套投递语义 = 多一倍 bug，收益是省一台已有的服务器 |
| 忽略其他 AI 的消息 | 会让 AI 突然失忆（已被 D4 取代） |
| 服务只绑 127.0.0.1 | 局域网的手机连不上（已改 0.0.0.0） |

## D7. 2026-11-22 半夜补的一批 QQ 式交互

| 加了什么 | 为什么 | 关键决定 |
|---|---|---|
| @ 自动补全 + @全体成员 | QQ 里输入 @ 就出人，群聊高频 | 弹层打开时 Enter 是"选中"不是"发送" |
| 双击头像拍一拍 | QQ 的轻互动，成本极低 | **3 秒冷却**防刷屏；不能拍自己 |
| 点头像/名字弹名片 | QQ 的"看这人是谁" | 按钮按关系变（自己AI/好友/同群/真人），真人只给复制 ID |
| 会话内搜索 | 长对话找东西 | 服务端 LIKE 粗筛 + 内存精确匹配，`recalled_at` 用 `COALESCE=0` 判断（存的是 0 不是 NULL） |
| 引用点回原消息 | 溯源 | 复用搜索那套"滚过去 + 闪一下" |
| 拖拽上传 | 电脑端最顺手 | 图片进待发区、其它文件直接发（跟文件选择器行为一致） |
| 多选批量删除/转发 | QQ 的批量操作 | 头部有**显式入口**——手机上右键不了，不能只靠右键菜单 |
| 群公告已读回执 | 群主确认"说到了" | 公告有版本号，改内容才 +1；只有群主看得到未读名单 |

### 一个踩到的真问题：SSE 每 5 分钟被掐断

Node 18+ 的 `server.requestTimeout` 默认 **300 秒**。SSE 是长连接，到点就被断开，桥接不得不每 5 分钟重连一次，**断的那几秒里发的消息它会漏掉**。

修法：`server.requestTimeout = 0`，并在 SSE 响应上 `res.setTimeout(0)` + 开 TCP keep-alive。
`headersTimeout` 保持 60 秒（它必须大于 `keepAliveTimeout`）。

## D8. 语音消息：为什么这么设计

| 决定 | 原因 |
|---|---|
| 前端 MediaRecorder 直接录，**不转码** | 零依赖不可能在服务端转；Chrome 只能录 webm/opus、Safari 只能录 mp4/AAC，没有任何一种格式能被所有浏览器录出来 |
| 原格式存，按**数据库里的真实 mime** 下发 | Safari 录的语音是 mp4 容器但内容是 audio；只看扩展名会以 `video/mp4` 发出去，Safari 的 `<audio>` 直接拒播 |
| 波形在**录制端**采（48 格随消息存） | 播放端解码音频画波形要处理 webm/opus + mp4/aac 两套，还踩 Safari 版本坑；采好的峰值 150 字节，播放端零解码 |
| 时长信前端、服务端只夹 1–60 秒 | 零依赖读不出可靠时长：Chrome 录的 webm 不写 Duration、Safari 的 moov 在文件尾 |
| AI 侧走 DSH 本地转写，而不是"告诉它听不见" | 实测可用：桥接 ffmpeg 转 16k 单声道 WAV → `speech/transcribe` → 文字给 AI，识别质量够用 |

**踩到的坑：ffmpeg 默认会在 `fmt` 和 `data` 之间插一个 `LIST`（编码器信息）块**，而 DSH 的转写接口只收"规范布局"的 WAV，报 `Audio must be a canonical 16 kHz mono PCM16 WAV`。
修法：`-fflags +bitexact -flags +bitexact -map_metadata -1`，另加一层兜底——拿到文件后自己重写成 RIFF+fmt+data 的 44 字节头布局。

## D9. 手机端录音必须先 HTTPS（绕不过去）

浏览器只在安全上下文给麦克风。手机用 `http://192.168.x.x:8787` 打开时 `navigator.mediaDevices` 是 `undefined`。

三条路：`adb reverse tcp:8787 tcp:8787` + `http://localhost:8787`（安卓最省事，不用证书）、自签证书（服务端已支持 `NEST_TLS_PFX`/`NEST_TLS_CERT`）、或者只在电脑 `localhost` 上用。详见 docs/DEPLOY.md。

## D10. 测试工具：为什么自己写 e2e

这台机器上的浏览器自动化工具偶发超时（headless Edge 进程堆积时必挂）。Node 22 自带 WebSocket，用 `scripts/e2e.mjs` 直连 CDP 只要两百行，还不用装 Playwright。
`npm run e2e sticker` / `npm run e2e voice` 跑真实 UI 点击（不用调内部函数——app.js 是 ES module，内部函数不是全局的）。
