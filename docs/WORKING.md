# 我们的合作方式

（2026-11-22 用户定义，按此执行）

## 三个阶段

### 阶段一（现在）
用户下发任务 → 我执行 → 汇报结果。

### 阶段二（下一步）
我**主动推断缺什么** → 列出候选和理由 → **问用户** → 得到同意 → 动手。

### 阶段三（最终）
我推断 → **自己做** → 做完通知用户，不需要事前同意。

### 什么时候可以进阶段三
用户说了算。默认策略：阶段二跑顺几轮、我没有踩过"自作主张做错"的坑，就由用户宣布进入阶段三。

## 阶段三也仍然要问的事（不可逆 / 影响外部）

这几类即使进了阶段三也要先问：

- **删数据**：删会话、删账号、清库、删媒体文件
- **动别人的东西**：其他用户的数据、别人的 AI 人设
- **对外发布**：推到远端仓库、公开发布、装到别人机器上
- **花钱**：买域名/证书/云服务
- **改这台机器的全局设置**：开机自启项、系统代理、防火墙规则

其余（加功能、改 UI、修 bug、写文档、跑测试、加脚本）都属于"自己做完通知"。

## 汇报格式（阶段三的"通知"）

1. 我判断缺什么、为什么
2. 做了什么、怎么验证的（数字/截图/日志）
3. 还剩什么没做、卡在哪
4. 需要用户做的事（如果有）

### 完成记录（2026-11-23 夜 · 登录慢 → 自动挑快路）
实测（手机，360×792）：
- 手机 → ts.net 公网：TLS 握手 5.5~8.5s，/api/server-info 总 7~10s，拉 app.js(58KB) 11.8s
  冷启动一次最坏 24.8s
- 手机 → 局域网 http://192.168.1.172:8787：总 22ms
结论：不是"登服务器慢"，是 Tailscale Funnel 从手机这边握手太慢；在家就该走局域网。

改法（mobile/www/app.js）：
- 地址框支持**一次填多个地址**（空格/逗号分隔），并行快速探活（1.5s）后挑能连的那条
- 「上次用的地址」按**整组**存；启动时整组一起测，自动选快的
- 换服务器页/「换一个服务器」不再清空地址，预填回输入框，点进入还是整组
- 地址页提示改成「局域网更快，公网外面用」

实测结果：
- 存了「局域网 + 公网」两条后，冷启动进入 **1.6s**（之前 24.8s）
- 从点图标到进入约 4s（含 App 启动）
- 开机自动进入也是整组测速，走局域网

### 完成记录（2026-11-23 夜 · 「进不去」的真正原因）
- 现象：点「服务器」后一直卡在「正在进入 Nest」，点哪都没反应。
- 根本原因：壳页面 CSS `.entering { display:flex }` 盖过了 `hidden` 属性的默认样式，
  所以「正在进入」这层遮罩永远盖在地址页上面（地址页其实渲染好了，只是被盖住、点不到）。
  修法：壳 style.css 末尾加 `[hidden] { display: none !important; }`
- 顺带加：一台服务器都探不通时不硬跳，回地址页并提示「可以先用本机世界」
  （用户确认这个"返回本地"的兜底是想要的）
- 实测（手机）：
  * 点右下角「服务器」→ 壳 0.23 秒
  * 世界列表：本机世界 · 当前 局域网5ms / BF-202610171727 局域网26ms · 公网备用
  * 点本机世界 → 127.0.0.1，2.5 秒，账号 手机本机
