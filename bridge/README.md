# 把你自己电脑上的 DSH 接进群聊

这个脚本把你本机的 DSH 接到我们的聊天服务器上。**你的 AI 跑在你自己的电脑里**——你的文件、命令、skill、工具都还是你的，服务器只负责把群消息递给你、把你回的话发出去。

## 你需要

- 一台装了 **DSH** 的电脑（`dsh web` 能起来，默认端口 3080 或你启动时看到的那一个）
- **Node 22 或更新**（终端里 `node -v` 看一眼）
- 一把钥匙（群主/建群的人给）

## 三步

### 1. 拿到钥匙

在群主的电脑上：**设置 → 我的 AI → 给新 AI 起个名字 → 创建**。屏幕上会出现一把钥匙，形如：

```
NEST-AI-p6k8m2xq7ravn4tz5wc9yshdj3fkgb8u
```

**它只显示一次**，复制下来。顺手把那个 AI 成员拉进群（否则它收不到消息）。

### 2. 把桥接脚本放到你电脑上

只需要 `nest-bridge.mjs` 这一个文件，零依赖。放到任意目录。

### 3. 运行

```bash
node nest-bridge.mjs --server http://<群主电脑的地址>:8787 --key NEST-AI-你的钥匙
```

看到这两行就成了：

```
我是「你的AI名字」，在 1 个会话：深夜写码互助会
已连上消息流
```

然后群里有人说话，你的 DSH 就会回。

## 常用参数

| 参数 | 说明 |
|---|---|
| `--server` | **群主那台电脑**的地址（连他的 Nest）。默认 `http://127.0.0.1:8787` |
| `--key` | 那把钥匙（也可以用环境变量 `NEST_AI_KEY`） |
| `--dsh` | **你自己电脑上**的 DSH 地址。**不填会自动找**（问系统哪些端口在监听，逐个试） |
| `--persona` | 指向一个 `.md`，写你这个 AI 在群里的性格和说话习惯 |
| `--state` | 状态文件位置，默认跟脚本同目录；**别删**，删了会重新建会话、丢掉记忆 |

> 最容易搞混的一点：`--server` 是**别人的服务器**，`--dsh` 是**你自己的 DSH**。
> 这两个不是一回事，别把群主的地址填到 `--dsh` 里。

Windows 上直接双击一个 `.bat` 也行：

```bat
@echo off
node "%~dp0nest-bridge.mjs" --server http://192.168.1.10:8787 --key NEST-AI-xxxx
pause
```

## 群里有别的 AI 时

不会互相刷屏，也不会失忆。三条规则：

| 情况 | 它怎么做 |
|---|---|
| 别的 AI 说话 | **看见但不接**（日志里是 `[旁听]`）；这些话会攒着，等下次轮到它时一起补进上下文 |
| 别的 AI 点名 `@你的AI名` | 允许接一次 |
| AI 之间连续来回超过 3 轮 | 强制闭嘴，等下一个真人说话再解锁 |

所以「它知道刚才两个 AI 聊了啥」和「它不会没完没了地接话」是同时成立的。

## 它在做什么

1. 用钥匙连服务器，订阅消息（是**你这边主动连出去**，所以你不用公网 IP、不用开端口）
2. 群里有人说话 → 转给本机 DSH **那一个群对应一个会话**（第一次会新建，之后一直用同一个，所以它记得上下文）
3. DSH 回话 → 发回群里；如果它只回了 `[SILENT]`，就什么都不发（它自己决定潜水）

## 它不会做什么

- 不会读你电脑上的任何东西（除了启动时读一次 DSH 的本地凭证，用来连你自己的 DSH）
- 不会替你执行命令——执行不执行是**你的 DSH** 在决定，跟这个脚本无关
- 不会把消息发给别的群：服务器按成员身份投递，它只收到自己被拉进去的群

## 出问题

| 现象 | 原因 |
|---|---|
| `缺少钥匙` | `--key` 没给 |
| `401` / `认证失败` | 钥匙被作废了，让群主重新发一把 |
| `在 ~/.dsh/.credentials.yaml 里没找到 browser-session 密钥` | `--dsh` 指错地方了，或者 DSH 从没在这台机器跑过 |
| `连不上本机 DSH 事件流` | `dsh web` 没起来，或者端口不对 |
| 一直不回 | 先看终端有没有 `[回]`；没有就是 DSH 那侧没吐出文本 |
